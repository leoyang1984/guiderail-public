# 用户体验模拟记录

2026-09-05，用户要求以用户身份判断功能是否真正解决长建议流失、忘记全局与当前位置的问题。本次在用户打开的真实 Chrome GuideRail 侧边栏操作，不是仅查看源码或模拟浏览器 API。

## 场景与边界

以正在进行的本地 TTS 升级对话为背景：已有环境 → 下载 1.7B 模型 → A/B 比较 → 长文流水线 → 风格设计。后续方向来自对话，可执行拆分和完成标准由测试者人工整理，仅用于体验模拟。

创建「用户模拟 · TTS升级（非真实进度）」独立项目，不运行命令、不实际下载模型、不发送 ChatGPT 消息。结束后对话已改回「TTS本地部署」，原项目仍为三个步骤、一个完成、无当前步骤，选中原先的 STEP-03。模拟项目保留，含五步路线和一个模拟问题；模拟进度不代表真实 TTS 进度。

## 实际操作与观察

| 操作 | 观察 | 用户意义 |
|---|---|---|
| 粘贴原对话的“第一阶段 / 第二阶段 / 第三阶段”路线 | 提示未找到清单，要求使用 `- [ ]` 或 `- [x]` | 自然建议不能直接进入计划，仍需人工转换 |
| 人工改写成五步清单并补充说明、标准 | 成功导入，保留各步详情 | 整理完成后能提供全局路线，但整理劳动由用户承担 |
| 将下载步骤设为当前 | 显示第 2 / 5 步、下一步 A/B 比较 | 可以明确当前位置与后续方向 |
| 添加“模拟：代理导致下载中断”问题与恢复说明 | 问题归属正确，顶部显示未解决数量 | 调试分支不会覆盖主线 |
| 关闭并重新打开侧边栏 | 项目、当前步骤和问题说明恢复 | 有助于中断后恢复工作记忆 |
| 将问题标记解决，再模拟完成下载 | 推进到第 3 / 5 步，问题保留 | 解决问题与推进主线的基本流程有效 |
| 查看后续 A/B 比较步骤 | 只有已录入的方向，具体命令仍需后续对话补充 | 显示下一步不等于该步已经可执行 |

## 产品判断

已经能帮助用户保留整理好的路线、进度和问题上下文。不能据此判断已完整解决长建议流失：入口转换、后续建议归档、阶段层级仍是主要负担。此前依据测试与功能齐全所作的判断偏乐观。

优先改进建议（尚未实施）：

1. 降低进入计划的成本：提供给 ChatGPT 的可复制规划格式，支持常见编号和标题预览；用户确认后保存，不能把不完整的推断当成既定计划。
2. 降低持续维护成本：允许把后续建议快速补入当前步骤，保存来源及恢复工作的提示，而不是每次手动拆标题、说明、标准。
3. 区分大阶段与当前具体动作：当前扁平列表把环境检查和长文流水线同等计数。数字完成比例仅表示条目完成数，不代表工作量或真实项目阶段。

下一轮应围绕“建议进入计划 → 后续建议补入 → 中断后恢复”改善体验，再用真实长任务验证；不宜继续用增加按钮数量作为达成用户目标的依据。

本次不包含完整备份恢复、浏览器重启测试或真实 TTS 操作，也不代表阶段 5、6 所有验收项都已通过。
