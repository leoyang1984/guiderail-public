# 阶段 5、6 统一验收

目标：即使主对话又增加几十轮讨论，仍不需要翻历史，就能确认整体路线、当前位置、操作内容及下一步。

## 准备

1. 在 `chrome://extensions` 刷新 GuideRail，关闭并重新打开侧边栏。
2. 在底部「备份与恢复」先导出当前全部数据。恢复操作会替换所有项目。
3. 打开一个测试用 ChatGPT 对话，新建并关联项目「执行引导验收」。
4. 将同目录 `execution-guide.md` 的内容粘贴到「粘贴 Markdown 计划」，预览并确认追加。

## 路线与步骤详情

- 导入后应有三个步骤、一个已完成。
- 点击「从 STEP-02 开始」，显示第 2 / 3 步、33% 已完成及下一步 STEP-03。
- 点击「查看当前操作」应定位到操作详情，详情顶部不应被固定导航挡住。
- 查看说明、命令、完成标准；编辑并保存其中一项，确认修改显示。
- 点击其他步骤仅查看内容，顶部当前进度仍保持 STEP-02。
- 向下滚动查看长说明或问题，计划导航仍可见；步骤列表可独立滚动。
- 「查看导入原文」可查看原始清单，包括没有归入字段的前言。

## 推进与异常分支

- 从 STEP-02 点击「完成并进入下一步」，应变为两个已完成、当前 STEP-03；原步骤不再是当前步骤。
- 可先将 STEP-03 改为阻塞，再将 STEP-02 设为当前并完成它：STEP-03 应保持阻塞，导航提示查看阻塞步骤，不把它自动改成当前。
- 在当前步骤添加未解决问题，再推进时应要求确认；确认后问题仍保留为未解决。
- 完成所有步骤后显示「计划已全部完成」，不显示不存在的下一步。如果前面还有未完成步骤，会返回前面的未完成工作。

## 导入与备份恢复

- 重复导入同样编号的清单应被阻止，不覆盖已有说明、问题或状态。
- 导出 JSON，在 Chrome 下载列表确认文件存在。
- 临时修改一个步骤标题，选择刚才的备份；校验后先取消替换，确认修改仍在。
- 再确认恢复：标题回到备份版本，操作说明、命令、完成标准、问题与对话关联均保留。
- 选择无效 JSON，应提示错误并保留当前数据。
- 关闭重开侧边栏，返回测试对话，确认当前位置与详细内容仍在。

## 最后的真实使用判断

拿一份真实的长建议导入，实际执行两三步。在 ChatGPT 里继续讨论或调试后，再看侧边栏：

> 能否立即回答：整个任务是什么、已完成多少、我在哪一步、这一步怎么做、什么结果算完成、接下来做什么？

如果某个答案仍需要翻聊天历史，请记录缺失内容或不方便的操作位置。这比单纯检查按钮更能判断 GuideRail 是否解决了你的痛点。

本工具不自动判断完成标准、不执行命令、不自动读取后续聊天。新的建议仍需手动补入步骤；按完成标准检查结果后，由用户主动推进。
