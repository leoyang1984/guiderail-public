用户反馈后，当前改为回复收藏与原文定位，见 [简化方案](../../SIMPLIFIED_REPLIES.md)。以下是历史规划，不再自动推进。

# GuideRail v0.2 开发计划

状态：Phase 1–2 代码已实现，自动测试及独立模拟页面验证通过，真实 Chrome 扩展验收待完成；Phase 3 代码与独立模拟验证已完成，真实扩展验收待完成；Phase 4–6 尚未实施。2026-09-05。

## 版本目标

让用户把 ChatGPT 中的建议直接收录为任务依据，在任务路线图中看见总目标、当前步骤和问题分支，中断或切换对话后仍能继续。

沿用已有项目、计划、步骤、问题、本地保存和串行写入机制。侧栏用于当前执行，独立扩展页面用于全局白板，两者共享同一份状态。

成功标准：用真实 TTS 场景完成“收录建议 → 建立路线 → 补充建议 → 记录问题 → 返回主线 → 换对话继续”，无需反复复制全文、翻找历史或重新整理已有计划。模拟进度与真实任务分开。

## Phase 1：消息来源与收录

- 增加仅面向 ChatGPT 页面的内容脚本适配层，读取已渲染消息的对话 ID、消息 ID、角色及可保存的文本（保留代码段）。
- 回复旁提供“收录”：关联已有步骤，默认推荐当前步骤；也可填写标题后创建步骤。没有关联项目时先选择或创建项目。
- 收录前显示目标步骤，保存消息原文快照、采集时间及来源。一个步骤可以关联多条消息，一条消息可以关联多个步骤；重复点击不重复建立同一关联。
- 仅保存用户主动收录的内容；流式回复未完成时不作为完整建议保存。页面结构不匹配时显示不可用状态。
- 引入新版存储及旧数据迁移，备份导出、恢复同步支持新字段和旧备份。迁移失败保留原数据。

验收：连续收录两条回复到一个步骤，切换对话不串绑；刷新后内容保留；原有项目、进度、问题及旧备份可继续使用。

## Phase 2：原文回溯与步骤资料

- 步骤详情显示关联建议，允许标为操作、问题处理或结论；解除关联不删除步骤。
- 点击“查看原文”打开或复用匹配对话，通过内容脚本按消息 ID 定位并短暂高亮，不依赖未验证的消息直链格式。
- 对未加载消息做有界定位尝试；找不到时明确提示，并显示保存的原文，支持用户加载历史后重试。不得定位到相似但错误的回复。
- 区分保存快照与页面当前内容；重新生成、编辑及分支变化导致的 ID 或内容变化，需要明确更新来源，不能静默替换。

验收：已加载回复可以准确返回；跨对话可以导航并尝试定位；不可定位时仍能阅读快照；重复内容不会造成错误匹配。

## Phase 3：总目标、阶段与可执行步骤

- 计划展示总目标与完成条件，增加“阶段 → 步骤”层级；已有步骤迁入默认阶段并保留 ID、状态和关联。
- 支持创建、调整阶段及移动步骤；计划保持唯一当前步骤，查看其他节点不改变执行进度。
- 步骤保留操作说明、命令和完成标准；阶段表示大方向，具体步骤承担执行。
- 提供将建议整理成计划的可复制提示词；支持常见标题、编号、清单的保守导入预览。含糊内容保留为原文，确认后才建立步骤。
- 进度标明“已完成步骤数”，不把条目比例解释为工作量完成度。

验收：真实长建议能经过预览形成阶段与步骤；旧数据不丢失；用户能指出总目标、所属阶段、当前动作及下一步。

## Phase 4：全局任务白板

- 在独立扩展页面提供自动排列的路线图：总目标 → 阶段 → 步骤；支持缩放、平移、折叠和“一键定位当前步骤”。
- 当前、完成、待办、阻塞状态清晰区分；步骤下展开问题分支及关联建议数量。
- 点击节点查看操作、完成标准和来源；从白板打开原对话。问题解决后可返回所属主线步骤。
- 白板与侧栏使用同一数据源；跨页面修改同步，不另建一套进度。
- 第一版连线只表达归属和执行顺序，不暗示已经实现复杂依赖调度。

验收：从白板找到当前节点、问题和来源；侧栏推进后白板同步更新；较长路线可折叠浏览且当前节点容易找到。

## Phase 5：跨对话执行与中断恢复

- 同一计划下收录不同对话的消息；沿用现有多对话绑定能力，并显示每条建议来自哪个对话。
- 问题分支可关联排错回复与处理结论。完成问题不自动完成主步骤，解决后提示返回主线。
- 提供继续工作卡：总目标、当前阶段/步骤、最近记录、未解决问题、下一步和完成条件。最近收录内容不等于已执行结果。
- 用户可记录“做到哪里 / 下次先做什么”，并复制带相关摘录的继续提示给新对话；不自动发送消息。

验收：在两个对话间完成收录与排错；关闭后重开能恢复位置和继续说明；新对话不会把主线进度回滚。

## Phase 6：真实任务验证与发布收口

- 使用独立模拟项目跑完整 TTS 流程：长建议入库、阶段整理、补充消息、问题分支、跨对话、关闭恢复、原文不可定位时查看快照。
- 检查旧版升级、新版备份往返、旧备份导入、多窗口同步及长路线操作。
- 记录收录操作负担、找回原文成功/失败情况，以及是否还需翻聊天才能判断下一步；修复阻断主流程的问题。
- 更新安装、权限变更、使用说明和验收记录；真实 Chrome 操作通过前不标记发布完成。补齐原阶段 5、6 尚未完成的备份与重启验收。

验收：用户能独立回答“目标是什么、现在在哪、为什么做这一步、卡在哪里、接下来做什么”，且能找到对应建议或其保存快照。

## 数据与实现约束

- 消息来源由 conversationId + messageId 标识，存储角色、页面 URL、正文快照和采集时间；步骤 ID 独立于消息 ID。
- 关联记录连接来源与步骤/问题，关系类型和备注归关联所有。解除关联不影响其他引用；删除节点按明确规则清理引用。
- Phase 3 引入阶段实体和步骤归属；每次模型变化均配套迁移、引用校验与备份支持。
- 消息 ID 已在当前页面验证可读，但网页结构及跨编辑/分支行为仍需实测。适配层失效不得破坏已保存的计划。
- 所有写入继续通过后台队列；页面提取内容视作数据，不作为扩展指令执行，展示时不执行原文 HTML。

## 版本边界与交付顺序

Phase 1 → 2 先交付“建议不流失、来源可回找”；Phase 3 → 4 交付全局路线；Phase 5 → 6 完成持续执行与验收。

本版暂不包含自由绘图、多人协作、云同步、自动运行命令、自动判断完成、复杂依赖调度及内置模型 API。自然语言自动拆解作为后续增强，当前用预览确认保证计划可核对。
