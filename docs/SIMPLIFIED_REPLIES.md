# v0.3：回到回复收藏与定位

用户反馈：阶段、任务与进度管理增加负担。当前目标改为找到长输出、保存原文并随时定位。暂停原 Phase 4–6 路线，不继续扩展任务管理或白板。

主流程：回复末尾“☆ 收藏这条回复” → 侧栏收藏列表 → 阅读保存原文 → 定位到原回复。无需创建项目或拆分步骤。

- 当前对话 / 全部收藏切换。
- 查找当前页面已加载的长回复：取至少 300 字符、最长的 5 条，可定位或收藏；不代表读取全部历史，也不自动判断哪条是计划。
- 新收藏保留正文结构，以白名单 React 元素呈现标题、列表、表格和代码；不执行原文脚本、事件或嵌入资源。旧版仅文本的快照仍按文本与代码显示。
- 管理 → 全选 → 删除所选，一次确认批量删除收藏。
- 数据与备份 → 清空全部本地数据，一次确认同时清理旧项目、阶段、步骤、问题与收藏。后台拒绝过期快照的清空请求。
- 已收录消息直接成为收藏；旧任务数据保留在备份中，未自动删除。重复收藏不会覆盖旧快照。

验证：模拟页面一键收藏、原文段落与代码呈现、定位高亮、批量选择；领域测试验证无任务收藏、去重、批量删除与旧引用清理、清空并发保护。真实 Chrome 仍需重新加载扩展并刷新 ChatGPT 后验收。

阅读页顶部“复制全文”复制保存的完整正文（包含代码与换行，不包含界面信息）。成功后显示“已复制”，两秒后恢复；失败可点击重试，不弹窗。

视觉更新：采用浅色阅读器样式；收藏列表显示标题、摘要与日期，阅读页固定返回/定位/复制操作。代码块及宽表格支持横向滚动。此次未进行浏览器视觉检查，由用户自行体验。

## v0.3.1 定位修复

定位找不到已挂载消息时，在对话滚动区域分段向上查找，必要时向下查找，每次等待页面挂载消息并按 ID 精确匹配。找到后确认回复进入可见区域再报告成功。查找最多约 40 秒；手动滚动、点击页面或切换对话会中止；失败时尽量恢复原滚动位置。页面结构、历史加载速度及分支变化仍可能造成定位失败，不保证任意长度对话都能定位。

代码测试覆盖虚拟化查找算法，未使用 computer use。真实验收：重新加载扩展并刷新 ChatGPT，收藏较早回复，继续生成新回复后再定位；观察旧回复是否重新加载并高亮。查找期间请暂不手动滚动。
